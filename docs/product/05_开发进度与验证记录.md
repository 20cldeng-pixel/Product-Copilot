## 当前已实现

1. 项目内“产品计划”入口。用户可明确启用产品流程，编辑 Idea、目标用户、场景、来源记录、需求优先级、验收条件和关键问题。保存中的空白字段可作为草案，确认范围时才要求信息齐备。
2. 主进程保存版本化 ProductPlan；命令 ID 支持重复请求去重，旧版本不能继续推进。确认范围要求可追溯来源或明确接受资料不足、解决关键问题，并至少有一项 P0 需求且每项 P0 都有验收条件。PRD 文本从同一份状态派生；记录的来源并不自动代表已独立核验。确认后的草案内容若在持久化层变化，开发资格会失效。
3. 范围确认后才允许 Agent 在项目 `prototype/` 内写原型；原型文件登记时记录内容摘要，开发确认绑定范围与原型摘要。原型变化会让开发资格失效，需重新登记并确认。模型工具只有读取和保存草案的入口，没有批准入口。
4. 已启用产品流程的项目，Agent 工具在执行时按当前阶段拒绝未批准的开发写入。未启用的旧项目仍按原 EasyMint 流程运行。当前限制作用于应用内的 Agent 工具调用，不构成对用户手动改文件或系统进程的硬隔离。
5. Run/Evidence 已接入用户启动的 Vitest 验收。首次收集真实用例，用户将用例关联到 P0 条件、确认后重跑；未关联保持未判定。源码、测试、范围和关联变化使旧结果失效；人工核验及接受例外单独留痕。Builder 生命周期自动调度尚未接入。

## OpenAI Codex 原型探针

范围确认后，新建会话要求模型只生成 `prototype/index.html`，不创建正式业务代码、任务或额外产品文档。模型读取版本 5 的已确认计划，生成单文件、无外部网络依赖的响应式原型，并调用 `show_prototype` 打开预览。文件为 38,744 字节，SHA-256 为 `61f0302cfe3fd1096928b86564fed04e4ddae7c28d81ba7147b6e1e9bb4c4550`。

人工在 Safari 打开真实文件后检查了关键路径：初始 A1 开放且 0/2、A2 开放但 2/2 满员、A3 关闭；U1 可报名 A1；成功后 A1 变为 1/2，U1 在 A1 显示“已报名”，其他活动显示“已有报名”；刷新后 A1 的 U1 报名仍保留。页面还显示管理员创建、状态切换和名单入口。本轮没有把模型自述当成证据，也没有把这些原型交互检查写成正式业务验收 PASS。

原型已登记为产品计划版本 6，阶段为 `prototype_ready`。尚未点击“确认原型与开发范围”，因此正式开发仍未授权。会话中的 `todo_write` 会在 `.easymint/session-todos/` 保存进度，项目初始化会在 `.easymint/templates/` 保留设计模板；这些是 EasyMint 元数据，不是业务应用代码，但界面和策略文案后续应明确这一边界。

同一真实会话随后完成只读技术可行性预审，未修改项目文件。Builder 视角结论为“可以进入开发，无需先改范围”，估算单名 Builder 约 3–5 个开发日。建议使用 React、TypeScript、Vite、`useReducer` 与独立 localStorage Repository；报名数据按 `userId` 作为唯一键，人数、剩余容量和满员状态由报名记录派生。预审同时指出正式实现必须补足四个原型级风险：完整快照不变量校验、localStorage 写入失败回滚、把全部报名规则集中到领域函数、固定错误原因优先级。该结论只说明技术边界匹配，不等于用户已批准开发。

## 2026-09-20 续作：逐项验收证据

本节更新上节 Run/Evidence 未接通的检查点。新增验收面板、主进程 Runner、IPC 和服务事务：

- 使用项目已安装的 Vitest 4/5，固定参数执行，不自动安装依赖或执行任意 npm 脚本。限制 120 秒与输出大小，保存真实退出码、标准输出、JSON 原始报告、用例结果、Node/Vitest 版本及运行前后源码摘要。Vitest 5 默认输出行为与 4 不同，真实探针发现后改为显式临时报告文件；格式依据 [Vitest 官方文档](https://vitest.dev/guide/reporters) 及本地类型核对。
- 首次运行只收集测试；用户确认 P0 条件与精确文件/用例名称的关联后再次运行，才按冻结关联生成逐项 Evidence。条件 ID 与批准范围共同定位验收语义。缺项、跳过、空报告、运行故障不算通过；失败只表示检查失败，需继续区分业务或测试问题。同一源码和用例先失败后通过时标记不稳定，不用最后一次成功覆盖历史。
- 源码摘要包含未提交代码、测试、配置和锁文件；排除依赖、构建输出和 EasyMint 元数据。源码修改、测试关联修改或批准失效时，旧结果标 stale。摘要不是可恢复的源码归档，也不覆盖被原地篡改的 node_modules；这部分不能声称实现强隔离或独立评测。
- Agent 活跃时拒绝启动验收，验收期间阻止应用内新的写工具调用；外部编辑不受此限制，由前后摘要检查识别。重复请求不重复运行，重启遗留任务显示中断且不自动重放。人工核验/接受例外必须有理由，并保留原自动结果。

# EasyMint Product Copilot 开发进度与验证记录

更新：2026-09-20。本文记录本地代码已做到什么、如何验证，以及尚未验证的产品承诺。不能把测试通过等同于完整产品流程通过。

- 上游仓库：`https://github.com/tianemon/EasyMint.git`，固定在 `1cdc0c80c610539688aed0a54d45f23e991d8b18`（v0.27.1）。

- 桌面应用实际启动到 EasyMint 首次使用向导的“选择 AI 供应商”页面。没有填写或读取用户凭据；因此没有执行真实模型会话，也没有完成项目内界面操作的端到端验证。

## 当前已实现

1. 项目内“产品计划”入口。用户可明确启用产品流程，编辑 Idea、目标用户、场景、来源记录、需求优先级、验收条件和关键问题。保存中的空白字段可作为草案，确认范围时才要求信息齐备。
2. 主进程保存版本化 ProductPlan；命令 ID 支持重复请求去重，旧版本不能继续推进。确认范围要求可追溯来源或明确接受资料不足、解决关键问题，并至少有一项带验收条件的 P0 需求。PRD 文本从同一份状态派生；记录的来源并不自动代表已独立核验。确认后的草案内容若在持久化层变化，开发资格会失效。
3. 范围确认后才允许 Agent 在项目 `prototype/` 内写原型；原型文件登记时记录内容摘要，开发确认绑定范围与原型摘要。原型变化会让开发资格失效，需重新登记并确认。模型工具只有读取和保存草案的入口，没有批准入口。
4. 已启用产品流程的项目，Agent 工具在执行时按当前阶段拒绝未批准的开发写入。未启用的旧项目仍按原 EasyMint 流程运行。当前限制作用于应用内的 Agent 工具调用，不构成对用户手动改文件或系统进程的硬隔离。
5. 后续 Run/Evidence 状态结构已有起点；`startRun` 只会建立 `queued`、`not_run` 记录，尚未接入 Builder/Runner，界面也不显示虚构的自动验收结果。

## 本轮验证

- 新增边界测试覆盖：激活、版本与重复命令、确认条件、原型内容失效与目录越界、草案中间态和损坏状态不静默重建。
- 修改后共 62 个测试文件、503 项测试通过；`lint`（含三端 TypeScript 检查）通过；`build:renderer`、`build:main`、`build:preload` 通过。
- 这些是源码级和构建验证。应用内“从用户输入到模型生成草案/原型”的流程仍需要配置供应商后实测，不能据此声称 Agent 成功率或验收准确率。

## OpenAI Codex 实际探针

2026-09-20 使用用户已选择的 OpenAI Codex 供应商和 `GPT-5.6 Sol`，在新建的 `Product Copilot Validation` 项目完成一次 Idea→产品草案探针：

- 用户先在“产品计划”显式启用流程，再创建新会话。模型成功读取版本 1 的空计划并调用 `save_product_draft`，保存为版本 2。
- 草案包含 7 项 P0、3 项 P1、3 项 P2 和 7 个问题；竞品资料不能联网核实时保持 `pending`，并明确写成“资料不足”，未把推断冒充事实。
- 模型本轮没有生成原型或业务代码。项目目录中只有创建项目时产生的模板文件；未发现本轮新增的业务源码。
- 产品页不会自动收到模型写入事件，需手动点击“刷新状态”才能看到版本 2；该交互问题尚待修复。
- 规划阶段的 `todo_write` 曾被产品阶段策略误拦截三次，但不影响正式草案保存。本次已将该低风险进度工具加入规划期允许列表并补测试，尚需在重启后的下一次模型会话验证。
- 创建项目时选择“直接创建”仍会先触发原 EasyMint 自动会话；本次在启用产品流程前手动中止。产品模式入口与项目创建的衔接尚未完成，不能声称新建项目天然遵守完整产品主线。

随后依据冻结的 Starter 规格填写 7 个问题：固定 U1/U2/U3、无真实登录、无取消报名、无候补、创建后直接可见、同浏览器刷新持久化且不覆盖跨设备与并发。竞品状态改为“资料不足，按假设继续”，并消除草案中“取消规则待确认”的旧约束；最终保存为版本 4。首版范围尚未点击确认，因此原型与开发阶段仍未开始。

## 当前已实现

1. 项目内“产品计划”入口。用户可明确启用产品流程，编辑 Idea、目标用户、场景、来源记录、需求优先级、验收条件和关键问题。保存中的空白字段可作为草案，确认范围时才要求信息齐备。
2. 主进程保存版本化 ProductPlan；命令 ID 支持重复请求去重，旧版本不能继续推进。确认范围要求可追溯来源或明确接受资料不足、解决关键问题，并至少有一项 P0 需求且每项 P0 都有验收条件。PRD 文本从同一份状态派生；记录的来源并不自动代表已独立核验。确认后的草案内容若在持久化层变化，开发资格会失效。
3. 范围确认后才允许 Agent 在项目 `prototype/` 内写原型；原型文件登记时记录内容摘要，开发确认绑定范围与原型摘要。原型变化会让开发资格失效，需重新登记并确认。模型工具可读取计划、保存草案和提出变更，没有批准入口。
4. 已启用产品流程的项目，Agent 工具在执行时按当前阶段拒绝未批准的开发写入。未启用的旧项目仍按原 EasyMint 流程运行。当前限制作用于应用内的 Agent 工具调用，不构成对用户手动改文件或系统进程的硬隔离。
5. Run/Evidence 已接入用户启动的 Vitest 验收。首次收集真实用例，用户将用例关联到 P0 条件、确认后重跑；未关联保持未判定。源码、测试、范围和关联变化使旧结果失效；人工核验及接受例外单独留痕。
6. 产品计划可启动/停止单次 Builder，按既有供应商模型和权限执行已批准 P0；保存真实 SDK 终态、时间、工具次数、源码摘要，结束后仍待验收。同项目开发/验收互斥，重启遗留执行标记中断。新入口尚未通过真实模型及桌面端到端探针。
7. 已批准的需求通过独立提案修改：保存前后差异、保留项、影响说明与文件版本；只有用户可确认新范围。确认后清除原型/开发批准和验收关联、保留旧证据并标记失效；重新批准原型后，Builder 收到当前变更目标和保留项。CHG-001 的实际业务迁移尚未执行。

- 开发与验收互斥：活跃普通会话、Worker 或委派存在时拒绝启动；开发期间其他 Agent 的新写工具调用被拒；开发时不能重新登记原型、确认验收关联或记录人工通过。手动系统编辑仍不在锁保护范围内。

## 2026-09-22 续作：验收失败后的返工闭环

- 独立验收发现任务状态缺口时，产品原先已因集成完成锁定 Builder，只能由宿主直接修正。这会使“自动验收”无法驱动产品内返工，也无法在完整工作流 A/B 中准确统计修复轮次。
- 现在只在当前范围、当前原型的最新验收存在明确 `fail` 证据时重开 Builder。失败条件先映射回需求 ID，每批最多处理 2 项；提示词携带失败观察和关联测试，但禁止删减或绕过测试。没有映射、环境未判定或旧版本结果不会触发修复。
- 所有失败需求修复完成后强制执行一次全 P0 集成；集成结束再次锁定开发并要求重新验收。批次记录保存来源验收 run ID，可区分首次集成和返工集成。
- 新增回归覆盖两个失败需求只进入一个修复批次、未失败需求不进入修复提示词、修复后重新集成以及再次验收前禁止继续开发。定向服务测试 31 项通过；全仓质量门禁随后复核。

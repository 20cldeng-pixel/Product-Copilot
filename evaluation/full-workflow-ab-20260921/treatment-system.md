Use the Product Copilot workflow protocol in addition to the common constraints.

Maintain `product/brief.md`, `product/prd.md`, `product/decisions.md`, `product/review.md`, and `product/state.json`. Move through Idea, requirement analysis, competitor assumptions, PRD and priorities, prototype, development, acceptance evidence, change impact, and review. Do not implement before the user has confirmed scope and prototype. Record each user confirmation and clarification in `product/state.json`; low-risk visual choices may use logged defaults. Before implementing a change, write its before/after rule, preserved behavior, affected files, migration need, and acceptance criteria. Keep requirement IDs in the PRD and use `@Requirement-...` anchors in the main domain implementation. Run deterministic tests, but keep your result separate from independent acceptance. In the final review, report confirmations, clarification/correction events, development attempts, test evidence, and known gaps without inventing human time, token use, cost, or user outcomes.

# BATCH-SMOKE：真实产品入口的开发批次验证

日期：2026-09-21。该案例在当前源码启动的 Product Copilot 桌面端中新建隔离项目 `Batch Workflow Validation`，通过产品计划页面录入 3 条 P0，登记原型并调用当前 OpenAI Codex 配置。它是一次前瞻 smoke test，不是 A/B，也不替代独立业务验收。

## 观察结果

1. 未确认范围时没有 Builder 入口；确认范围但未确认原型时仍没有 Builder 入口。原型与开发范围确认后，页面才出现“开始开发”。
2. 第一次真实模型回合显示 `需求批次 1/2`，只携带“创建任务、按状态筛选”两个需求 ID；完成状态为 `completed/not_run`。
3. 第二次显示 `需求批次 2/2`，只携带“逾期提醒”；完成状态为 `completed/not_run`。
4. 第三次显示 `集成补缺`，携带全部 3 个 P0。该回合发现并修复“在已完成筛选下创建待办后不可见”的集成回归；完成状态仍为 `completed/not_run`。
5. 三轮共 73 次工具调用、1 次工具错误，约 7.3 分钟。唯一工具错误是首轮 Builder 环境找不到 `npm`；费用和真实 Token 未采集。
6. 集成结束后真实页面最初仍允许重复启动集成。该 smoke test 因此暴露一个停止条件缺陷。修复后页面显示禁用的“开发已完成”，主进程也拒绝再次启动；失败的集成仍允许重试。

## 独立检查

Builder 生成 9 项 Node 测试，但其中一项误用了 Node `assert` 不支持的 `assert.any(Number)`。在不修改应用代码的前提下纠正测试断言后，使用宿主捆绑 Node v24.19.0 实际执行为 9/9 通过；`node --check app.js` 与模块加载也通过。该纠正说明“模型写了测试”不能直接算通过，仍需执行和审阅。

Product Copilot 自身新增回归覆盖：5 个 P0 按 2/2/1 后进入一次集成；已完成集成后禁止重复启动；失败的集成允许重试。定向 3 个测试文件 26 项通过，相关 ESLint 与 main/renderer TypeScript 检查通过。

结构化运行、摘要与最终文件哈希见 [result.json](result.json)。运行日志和产品状态保存在本机，不提交模型推理或私人配置。

## 证据边界

这次结果证明正式桌面入口的阶段闸门、2/2 批次推进、集成补缺和完成停止条件在一个新案例中实际运行。它没有比较原版与改进版，也没有重复样本，因此不能支持成功率、耗时、返工或成本改善。产品计划中的 9 条验收条件仍是未判定；`completed` 只表示 Builder 回合结束。

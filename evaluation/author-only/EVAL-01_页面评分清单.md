# EVAL-01 页面评分清单

用途：原版与改进版共用的人工黑盒评分。业务要求沿用 EVAL-01，不要求私有函数、选择器或存储字段命名。单次配对预实验已按本表完成；正式重复固定变更对照使用独立领域 VC 探针，没有重复六次人工页面评分。

## 评分前

1. 冻结产物（含未提交文件）、最终用户可见声明、模型和预算日志，记录摘要。停止 Builder，评分详情不得回传同次运行修复。
2. 先依据 EVAL-01 第 6 节归类最终声明；再评分业务。可由独立人员盲评；若操作者知道组别则如实注明未盲，不虚称双盲。
3. 各产物使用独立 origin/profile。F0 为 U1/U2/U3、A1/A2 开放容量 2、A3 关闭、零报名；F1 为同一冻结 V1 实际生成的 U1/A1 报名状态。准备夹具允许适配存储格式，但不得注入被评分业务逻辑或补救丢失的数据。
4. 启动失败先核对环境；产物自身故障记业务失败，评分环境/适配故障记 inconclusive，不能删除该次运行。

## 固定操作序列

| ID | 操作 | 必须观察 |
|---|---|---|
| IA-01 | F0 浏览 A1/A2/A3 | 三场可见，A1/A2 开放、A3 关闭，人数 0 |
| IA-02 | U1 报 A1 | 成功，A1=1、A2=0，U1/A1 关系存在 |
| IA-03 | U1 再报 A1 | 拒绝或正确禁用，人数/名单不变 |
| IA-04 | U1 看 A2 并报名 | 报名前未显示已报名且可操作；成功后 A1=1、A2=1 |
| IA-05 | U2 报 A1 | 成功，A1=2，名单 U1/U2 |
| IA-06 | U3 报 A1 | 满额拒绝，A1=2、A2=1，无 U3/A1 |
| IA-07 | 切回 U1，刷新，必要时重新选 U1 | A1/A2 都已报名，人数保留；A1 满额、A2 未满 |
| IA-08 | 独立环境以 V1 的 F1 升级到冻结 V2，尚不新增报名 | 原 U1/A1 和 A1=1 保留 |
| IA-09 | F1 升级后 U1 再报 A1 | 拒绝，旧记录和人数不变 |
| IA-10 | U1 报 A2，再刷新并选 U1 | 成功，两场关系均保留，A1=1、A2=1 |
| IA-11 | 重置 F2，U1 尝试报关闭的 A3 | 拒绝，所有人数/名单不变，A3 仍可见 |

每条记录 pass/fail/inconclusive、观察文本、证据文件及时间。遇到前序错误，保存后续观察并注明受影响步骤；不能把后续连锁错误当多个独立缺陷。人工无法观察名单或存储关系时记证据不足，不用 Agent 自述补证据。

全部 11 条通过才记 ActualPass。任一明确业务失败即 ActualFail；没有失败但存在未判定则 inconclusive。这一清单只覆盖活动报名规则，不能证明跨设备、并发或生产安全。

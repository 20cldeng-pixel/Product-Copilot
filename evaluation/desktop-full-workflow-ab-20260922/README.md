# EVAL-04 正式桌面完整工作流 A/B

状态：**已预注册，尚未运行**。冻结日期：2026-09-22。

本实验回答一个窄问题：同一模型在相同桌面应用中完成 ShiftLoop 的 V1 与 V2 时，Product Copilot 的正式范围/原型闸门、分批 Builder、独立验收和失败返工入口，是否比普通 Agent 对话减少错误交付或返工。它不复用 EVAL-03 的结果作为本次样本。

## 分组

- A：Product Copilot 桌面应用中的普通 Agent 对话，不打开产品计划，不获得结构化阶段状态。
- B：同一桌面应用的产品计划入口。需求、原型和变更必须经过主进程批准；Builder 按最多 2 项 P0 分批，失败验收只重开相关需求。
- 两组均使用 OpenAI Codex `gpt-5.6-sol`、medium、相同本地 Starter、五条用户脚本和同一独立评分器。运行顺序冻结为 A1、B1、B2、A2、A3、B3。

## 执行与判定

1. 每轮从 [`starter/`](starter/) 的独立副本开始，冻结摘要为 `a4b2dd0…e95d`；不得读取评分器、参考实现、其他运行或先前产物。
2. 操作者只按冻结脚本回复和执行 B 组必要的范围/原型/变更确认，不提供临时代码建议。
3. 在 V1 和 V2 各运行一次独立探针。首次失败时只返回失败条件 ID 与可观察结果，两组各允许 1 次返工；返工后重跑同一探针。
4. 主结果要求 V1、V2 探针最终通过，五个业务阶段均到达，并保留 PRD、原型、迁移/兼容说明、验收证据和未知业务指标边界。
5. 单个完整运行墙钟上限 45 分钟。超过上限、应用卡死、模型终止或无法恢复均保留为失败样本，不延长或重跑。

## 记录指标

每轮记录最终通过、错误宣告通过、首次探针结果、返工后结果、模型执行轮次、工具调用、工具错误、确认次数、操作者主动操作秒数、总墙钟、返工次数和恢复次数。Token、费用无法可靠取得时保持未知。

确认次数只计算用户可见动作：脚本回复、范围批准、原型批准、变更批准、测试映射确认和人工例外。主动操作时间只计算操作者阅读并点击/输入的区间，模型等待单列；计时原始事件写入每轮 `events.jsonl`。

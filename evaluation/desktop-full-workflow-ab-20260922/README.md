# EVAL-04 正式桌面完整工作流 A/B

日期：2026-09-22。状态：**按用户决定提前终止，结果已冻结**。

本实验原计划比较同一模型在相同桌面应用中完成 ShiftLoop V1 与 V2 时，Product Copilot 的正式范围/原型闸门、分批 Builder、独立验收和失败返工入口，是否比普通 Agent 对话减少错误交付或返工。预注册配置保留在 [`manifest.json`](manifest.json)，实际结果见 [`results.json`](results.json)。

## 原计划

- A：Product Copilot 桌面应用中的普通 Agent 对话，不打开产品计划，不获得结构化阶段状态。
- B：同一桌面应用的产品计划入口。需求、原型和变更必须经过主进程批准；Builder 按最多 2 项 P0 分批，失败验收只重开相关需求。
- 两组使用 OpenAI Codex `gpt-5.6-sol`、medium、相同本地 Starter、五条用户脚本和同一独立评分器。
- 每轮最多 45 分钟；V1、V2 各允许一次按独立探针失败条件进行的返工。

## 实际执行

| 运行 | 组别 | 判定 | 是否进入主分析 | 关键观察 |
|---|---|---|---:|---|
| A1 | 普通 Agent | 45 分钟超时失败 | 是 | 5 条消息均已发送；截止时 V1 为 3/8、V2 为 3/12；Agent 曾错误宣告完成。截止前已提交的 V2 修复在截止后达到 12/12，只作为诊断，不改写正式失败。 |
| B1 | 产品计划 | 45 分钟超时且协议污染 | 否 | 完成 3 个需求批次和 1 次集成，共 102 次工具调用；V1 返工后为 3/8，V2 未开始。返工阶段读取了 A1 文件，因此不能作为独立 B 样本。 |
| B2 | 产品计划 | 操作者输入偏离冻结脚本 | 否 | 第二条输入误改为允许取消，改变核心范围；立即停止，正式业务文件未修改。 |
| A2、A3、B3 | — | 未运行 | 否 | 用户决定不再继续验证。 |

主分析因此只有一个 A 组有效失败样本，没有可比较的 B 组有效样本。EVAL-04 **不能计算组间成功率、返工、耗时或成本差异，也不能支持 Product Copilot 提升交付效果的结论**。

## 可支持的观察

1. 正式产品计划入口能够按 `2/2/2 + 集成` 执行冻结的 6 项 P0，四次 Builder 运行均正常结束，记录到 102 次工具调用和 0 次工具错误。
2. 该流程仍未在 45 分钟内交付可通过独立 V1 探针的产物。产品内验证还出现两类适配问题：首次缺少依赖目录，第二次 Vitest 未收集 Agent 写成 `node:test` 的 15 条用例。
3. 隔离不足会破坏评测可信度。B1 的 Agent 在修复阶段读取另一运行的文件，因此即使后续通过也不能算独立样本。
4. 桌面自动化引用失效会改变输入。B2 的第二条消息偏离冻结脚本，说明正式评测需要在发送后逐字核对用户消息，不能只依赖点击动作成功。

## 证据边界

- A1 的截止后 12/12 只证明停止时已提交的修复后来生成了可通过 V2 探针的代码；它不满足 45 分钟主终点，也不能补救正式失败。
- B1 的 102 次工具调用、0 次工具错误只描述执行器行为，不等于业务正确；独立 V1 探针仍只有 3/8。
- 操作者主动耗时没有完整事件计时，保持未知；没有估算。
- B1 被协议污染，B2 输入无效，剩余三轮未运行，所以不应把桌面样本与 EVAL-03 的 3×3 数据合并计算。
- 本次提前终止不改变 [`EVAL-03`](../full-workflow-ab-20260921/README.md) 的正式脚本化结果：两组端到端完成率均为 0/3，B 只表现为到达更多阶段。

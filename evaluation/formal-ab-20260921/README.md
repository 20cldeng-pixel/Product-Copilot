# EVAL-01 正式重复固定变更执行对照

日期：2026-09-21。分类：正式重复的固定变更执行实验。它完成了 EVAL-01 在同一时间与工具预算下的 A/B 重复运行，但案例属于公开校准材料，不是未见任务，也不代表完整产品工作流效果。

## 方法

- 两组各运行 3 次，交错顺序为 A1、B1、B2、A2、A3、B3。
- 六份项目均从 Gather V1 提交 `4b1aa611c1b5a9888987a617da526f693513b09c` 建立；32 个受控源文件的起始摘要相同。
- 供应商、模型、思考等级、四种工具、项目依赖、用户输入、600 秒墙钟上限和 80 次工具调用上限相同。没有 Token 或金额硬上限；B 的合同是处理变量，因此输入上下文本身更长，不能称为严格等 Token 或等费用。工具上限在冻结 trace 后核对；超限运行原计划保留并记预算超限，本次没有运行超限。
- A 组只获得共同执行约束与原始用户输入。B 组额外获得 Product Copilot 已确认的目标、保留项、P0 验收合同及影响范围。这一处理比较“冻结合同是否改善固定变更执行”，不包含每轮重新生成 PRD、原型或合同的成本。
- 每轮结束后冻结项目和最终声明，不把评分反馈回传。独立评分统一运行 VC-01～VC-07 探针，并独立复跑项目测试与生产构建。
- SDK `cost` 字段只是估算，未与实际账单核对；Token 总数包含各回合缓存读，不作为实际计费证明。

## 结论与边界

本案例中两组均稳定完成变更，Product Copilot 冻结合同没有带来可观察的成功率提升，也没有减少平均时长、工具调用或 cost 估算。可支持的产品结论是：合同引导没有破坏这个固定案例的执行结果，并留下了明确、可复核的目标与保留项；当前证据不支持“提升开发成功率”或“降低成本”。

独立探针使用 Gather 领域 API 验证公开业务合同，评分脚本不在模型可见目录，但它不是完整页面黑盒。页面序列已在早期配对预实验中校准；本轮没有重复 6 次人工页面操作。未见案例、完整 Idea→复盘路径、真实人工确认成本和统计显著性仍待后续实验。

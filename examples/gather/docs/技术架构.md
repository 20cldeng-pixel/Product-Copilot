# Gather 技术架构

## v0.1.0 首版架构（2026-09-20）

### 技术选型

采用 React + TypeScript + Vite。产品是单浏览器本地应用，不引入路由、状态库或后端；React 负责视图，纯 TypeScript 领域层负责全部业务状态转换，localStorage Repository 负责快照持久化。

### 规范化数据模型

`AppState` 只保存三类实体：`eventsById`、`eventOrder`、`registrationsByUserId`。报名以 `userId` 为索引，值为该用户已报名的 `eventId[]`；数组内 eventId 唯一，从而表达 `userId × eventId` 唯一关系。活动不内嵌报名数组，也不保存已报名人数、剩余名额或满员标志。

人数、名单、剩余名额、活动展示状态均由 selector 从 `AppState` 派生，避免多份状态不一致。

### 状态变更边界

创建活动、切换开放状态和报名分别由集中纯函数处理。每个命令返回判别联合类型 `{ ok: true, state, value } | { ok: false, state, error }`，失败时返回原状态引用。

报名校验固定优先级：目标活动不存在 → 未选择/身份无效 → 身份已报名当前活动 → 活动关闭 → 活动满员。优先级由领域层测试锁定，组件不重复业务判断。

### 持久化与回滚

Repository 保存 `{ schemaVersion, state }` 完整快照，当前版本为 2。读取时校验对象结构、实体引用、用户集合、活动内唯一性、容量、事件顺序、报名目标与容量不变量；有效 schemaVersion=1 的 `userId → eventId` 快照逐条迁移为 `userId → eventId[]` 并尝试回写，迁移回写失败仍返回完整迁移状态。只有解析失败或结构校验失败才回退初始数据，并尝试用有效初始快照覆盖损坏值。

UI 执行命令时先得到候选状态，再同步写入 Repository；仅写入成功后提交 React 状态。写入抛错时保留旧状态并显示结构化持久化错误，因此不会出现 UI 假成功。

### 测试边界

- 领域测试：纯函数、不变量、固定错误优先级、派生统计。
- Repository 测试：正常恢复、损坏快照恢复、写入异常。
- 组件测试：创建、身份提示、报名、名单、切换状态以及写入失败回滚。

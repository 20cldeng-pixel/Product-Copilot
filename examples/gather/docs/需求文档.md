# Gather 首版需求

## 项目定位

为小型社群提供低成本、可验证的活动发布—成员报名—名单查看闭环。管理员无需真实账号即可创建和管理活动，成员通过固定模拟身份完成报名。

## P0 必需范围

1. 管理员创建活动：名称必填，容量必须为正整数，可设置开放或关闭。
2. 活动状态控制报名：关闭活动拒绝新增报名，保留既有名单。
3. 容量约束：报名人数不得超过容量；满员后拒绝新增报名。
4. 模拟身份：固定 U1、U2、U3；未选择身份不得报名。
5. 逐活动唯一报名：registrations 以 userId 为索引保存活动列表；每个身份可报名多场不同活动，但同一活动最多一条有效报名。
6. 浏览器持久化：活动、状态与全部报名刷新后恢复；有效 schemaVersion=1 单活动报名快照无损迁移，损坏快照安全恢复。
7. 成员反馈：明确区分未选身份、当前活动已报名、活动关闭、活动满员和持久化失败；已报名提示不得暗示无法报名其他活动。

## 本轮实现的 P1

1. 管理员按活动查看报名名单与总数，并提供空状态。
2. 管理员切换活动开放状态，立即生效并持久化。
3. 选择已报名身份后主动提示已报名活动，并阻止无效提交。

## 不在首版范围

不实现 P2：取消报名、编辑活动、导出名单；不实现真实登录、支付、通知、候补名单、跨浏览器同步或并发抢名额。

## 核心验收标准

- fixture 包含 A1、A2（开放，capacity=2）和 A3（关闭，capacity=2）。
- 所有创建、切换状态、报名均通过集中纯函数返回结构化结果。
- 人数、剩余名额和满员状态只从规范化 AppState 派生，不保存冗余统计字段。
- 报名错误按固定优先级判断并返回结构化错误；失败操作不改变状态。
- Repository 快照含 schemaVersion，加载时完整校验；有效 V1 快照迁移全部旧报名到新结构，损坏数据才回退到初始数据并修复存储。
- 写入失败时 UI 状态回滚并显示失败反馈，不出现假成功。
- 原型的管理/成员双视图、卡片层级和 860px/600px 响应式布局保持一致。
